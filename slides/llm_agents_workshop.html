Section 1

What is a Large Language Model?

The core idea: an LLM is a function:
Text In → [ LLM ] → Text Out
Trained on vast amounts of text, it learns to predict what comes next — and follows instruction-style prompts.
Key properties:
  • Generative — creates novel text
  • Instruction-following — responds to task prompts
  • Context-aware — uses the full prompt as context
INPUT PROMPT
"Translate to French:
Hello, world."
▼
LLM  (gpt-4o-mini)
▼
"Bonjour, le monde."
OUTPUT

Next-Token Prediction, Step by Step

The model never writes a whole sentence at once: it picks one token, appends it, and repeats

Probabilities for the next token

Low temperature sharpens the distribution (predictable). High temperature flattens it (more creative / random). Here we always pick the top token (greedy). Numbers are illustrative.

Section 1

Why LangChain?

A framework that makes LLMs easy to compose, connect, and control.

📝

Prompt Templates

Reusable, parameterized prompts — fill variables at runtime, no string hacks.

⛓️

Chains

Compose prompt + LLM into one callable unit. Chain multiple steps together.

🤖

Agents

LLMs that decide which tools to call. They reason, act, and observe in a loop.

Template+LLM=Chain → LLM+Tools+Loop=Agent

Section 2

  
Chains vs. Agents

  

    

      

        
⛓️  Chain

        
Predetermined steps. Runs the same way every time.

        
Best for: structured pipelines · predictable workflows · fast, deterministic tasks

        
Step 1→Step 2→Step 3

        
Always the same path

      

      

        
🤖  Agent

        
Dynamic steps. LLM decides what to do next.

        
Best for: questions requiring tool use · multi-step reasoning · open-ended tasks

        
Reason→Act→Observe

        
↺ repeats until answer found

      

    

    
A chain is a fixed recipe; an agent is a cook who decides the next step after tasting the dish.

  







  
Section 2

  
The ReAct Pattern

  
ReAct = Reason + Act — the model thinks, then acts, then observes the result.

  

    

      
1
Thought
LLM reasons about what it knows and what it still needs

      
→

      
2
Action
LLM picks a tool and provides the exact input to call

      
→

      
3
Observation
The tool runs and returns a result back to the model

    

    

      ↺ repeat until enough information→
      Final Answer
    

    
Source: “ReAct: Synergizing Reasoning and Acting in Language Models” — Yao et al., 2022

  







  
Section 2

  
Tools — Extending the LLM

  
LLMs are great at reasoning — bad at precision tasks (exact math, live data, code). Tools bridge that gap.

  

    

      
🧮
@tool calculator
Evaluates math expressions. No hallucinated numbers.

        
calculator('math.sqrt(256)')
→ 16.0

      
🌍
@tool capital_lookup
Queries a dictionary for capitals — deterministic, always right.

        
capital_lookup('france')
→ 'Paris'

      
📝
@tool word_counter
Counts words in a string — simple but illustrative.

        
word_counter('hello world')
→ '2 words'

    

  







  
Anatomy of a Tool

  
The LLM never runs your Python. It only reads the tool's name, description and arguments.

  

    

    

      

        
1 · YOUR PYTHON FUNCTION

        

      

      
→

      

        
2 · TOOL OBJECT (from @tool)

        

      

      
→

      

        
3 · WHAT THE LLM SEES IN ITS PROMPT

        

      

    

    
The docstring is the instruction manual. A vague description → the agent picks the wrong tool or passes bad input.

ReAct in Action — A Concrete Trace

  
Question: “What is the capital of Japan and how many letters does its name have?”

  

    

      
THOUGHTI need to find Japan's capital. I'll use capital_lookup first.

      
ACTIONcapital_lookup("japan")  →  Observation: "Tokyo"

      
THOUGHTGood. Now I need to count the letters in "Tokyo". I'll use word_counter.

      
ACTIONword_counter("Tokyo")  →  Observation: "1 word"  /  len = 5 letters

      
FINAL ANSWERThe capital of Japan is Tokyo. It has 5 letters.

Section 3

  
LLMs Are Stateless — The Problem

  
Every API call is completely independent. No memory of previous messages.

  

    

      
.invoke() call #1

      
HUMANMy name is Alice.

      
AINice to meet you, Alice!

      
.invoke() call #2 — fresh start

      
HUMANWhat is my name?

      
AII don't know your name. ❌ (forgot!)

    

    
Each .invoke() call is a fresh start — the model only sees what is in the current prompt.

  







  
Section 3

  
Memory — Making Agents Stateful

  
The fix: inject the conversation history into every new prompt.

  

    

      

        
How ConversationBufferMemory works

        

          
▸ 1. User sends a message
▸ 2. Buffer prepended to prompt
▸ 3. Full context sent to LLM
▸ 4. Response stored in buffer
▸ 5. Buffer grows each turn

        

      

      

        
Memory Types

        
ConversationBufferMemoryFull history verbatim · Best for: short chats

        
ConversationSummaryMemoryLLM-summarizes history · Best for: long sessions

        
BufferWindowMemoryLast N turns only · Best for: fixed context

      

    

    
In the notebook we use ConversationBufferMemory — most transparent for learning.
