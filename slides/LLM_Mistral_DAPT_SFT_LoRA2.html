¿Qué es un Large Language Model?

Un LLM es una red neuronal (Transformer) entrenada en cantidades masivas de texto para predecir el token siguiente. Al hacerlo a escala, emerge la capacidad de razonar, resumir, traducir y generar código.

"El paciente presenta fiebre y"
→
Transformerself-attention × N capas
→
P(token siguiente)" tos" 0.31 · " dolor" 0.22 · " malestar" 0.12 …

Transformer

Arquitectura basada en mecanismo de atención (self-attention). Encoder-Decoder o solo Decoder.

Tokens

Unidades de texto sub-palabra. GPT-4 usa ~100 k tokens. Los LLMs predicen distribuciones sobre tokens.

Escala

Ley de escalado: más parámetros + más datos + más cómputo → mejor perplejidad y capacidades emergentes.

Mistral 7B — Innovaciones Arquitectónicas

Grouped-Query Attention (GQA)

En Multi-Head Attention clásica cada cabeza Q tiene su propia K y V. GQA agrupa varias cabezas Q para compartir K y V → reduce memoria KV-cache en inferencia sin degradar calidad.

Sliding Window Attention (SWA)

Cada token solo atiende a los W tokens anteriores (W=4096). Complejidad O(n·W) en vez de O(n²). El flujo de información a larga distancia se propaga a través de capas apiladas.

RoPE — Rotary Position Embedding

Codifica posición relativa rotando vectores Q y K en el espacio complejo. Permite extrapolar a contextos más largos que los vistos en entrenamiento.

SwiGLU Activation

Función de activación en la MLP: SwiGLU(x) = Swish(xW) ⊙ (xV). Mejora empíricamente la perplejidad sin costo significativo de cómputo.

Las dos siguientes diapositivas exploran GQA y SWA de forma interactiva.

MHA vs. GQA vs. MQA: ¿quién comparte K y V?

Cada línea une una cabeza de consulta (Q) con la cabeza K/V que usa. Menos cabezas K/V → KV-cache más pequeño.

Dibujo simplificado a 8 cabezas Q. Mistral 7B real: 32 cabezas Q y 8 cabezas K/V (grupos de 4).

Domain-Adaptive Pretraining (DAPT)

Modelo Base(Mistral 7B)
→
Corpus de Dominio(continúa entrenando)
→
Modelo Adaptadoal dominio

¿Qué es?

Continuar el preentrenamiento (next-token prediction) sobre un corpus especializado, SIN cambiar la arquitectura.

¿Cuándo se usa?

Cuando el dominio tiene vocabulario, estilo o conocimiento muy diferente al corpus de preentrenamiento: medicina, derecho, código, finanzas, biología molecular, etc.

Diferencia con SFT

DAPT no requiere etiquetas ni pares instrucción-respuesta. Solo texto en bruto del dominio. Ajusta las representaciones internas y la distribución de tokens del dominio.

Señal de entrenamiento

Cross-entropy loss sobre el token siguiente. Misma función de pérdida que el preentrenamiento original.

DAPT — Datos, Proceso y Consideraciones

Recopilación del corpus

Artículos científicos, manuales técnicos, foros especializados, código fuente. Mínimo ~1 GB de texto limpio para DAPT significativo.

Tokenización y preprocesamiento

Usar el mismo tokenizador del modelo base. Limpiar duplicados, artefactos HTML, texto de baja calidad (perplejidad demasiado alta/baja).

Hiperparámetros típicos

LR: 1e-5 a 5e-5 · Batch: 512–2048 tokens por GPU
Épocas: 1–3 · Warmup + cosine decay

Mezcla con datos generales

Para evitar olvido catastrófico, mezclar ~10–20 % de datos web generales con el corpus de dominio.

Riesgos y mitigaciones

⚠ Olvido catastrófico

El modelo pierde capacidades generales. → Mezcla de datos, LR baja, pocas épocas.

⚠ Distribution shift

Corpus muy pequeño sobreajusta. → Aumentar datos o reducir pasos.

⚠ Tokenización fuera de vocabulario

Términos técnicos se fragmentan en muchos tokens. → Evaluar coverage; a veces se extiende el vocab.

⚠ Evaluación

Medir perplejidad en corpus de validación del dominio + benchmarks generales para detectar regresión.

Mezcla de datos y olvido catastrófico

Mueve el porcentaje de texto general que entra en cada batch de DAPT

Un batch de entrenamiento (cada bloque ≈ una secuencia)

corpus de dominio (p. ej. artículos médicos)texto web general

Barras cualitativas e ilustrativas: muestran la tendencia, no mediciones. En la práctica se verifica con perplejidad del dominio + benchmarks generales (MMLU, HellaSwag…). Zona recomendada: 10–20 %.

Supervised Fine-Tuning (SFT)

SFT transforma un modelo base (que predice tokens) en un asistente que sigue instrucciones. Se entrena con ejemplos [Instrucción → Respuesta] usando cross-entropy sobre la respuesta.

Modelo Base
→
Dataset de Instrucciones
→
SFT(fine-tune)
→
Modelo Instruct

¿Qué aprende el modelo?

A formatear respuestas, seguir el rol de asistente, respetar restricciones dadas en el prompt y adaptar el tono al contexto.

Diferencia con DAPT

DAPT ajusta representaciones de conocimiento (qué sabe el modelo). SFT ajusta el comportamiento (cómo responde).

Combinación habitual

Primero DAPT sobre dominio → luego SFT con instrucciones del dominio. Así el modelo es experto Y útil.

SFT — Proceso de Entrenamiento

① Curación del dataset

Calidad >> cantidad. 1 000–10 000 pares de alta calidad superan a 100 000 pares ruidosos. Fuentes: Alpaca, FLAN, OpenAssistant, datasets de dominio etiquetados manualmente.

② Tokenización y máscara de pérdida

Solo se computa la pérdida sobre los tokens de la RESPUESTA, no sobre la instrucción. Esto evita que el modelo aprenda a 'repetir preguntas'.

③ Hiperparámetros

LR: 1e-4 a 3e-4 · Epochs: 1–5 · Batch efectivo: 64–256
Scheduler: cosine con warmup del 3–5 % de los pasos.

④ Evaluación

Benchmark de instrucciones: MT-Bench, AlpacaEval, métricas de dominio. Comparar con el modelo base para cuantificar la ganancia.

¿Sobre qué tokens se calcula la pérdida?

Compara DAPT, SFT sin máscara y SFT con máscara. Los tokens tachados reciben la etiqueta -100 y se ignoran.

¿Por qué necesitamos PEFT?

Actualizar todos los parámetros de Mistral 7B requiere ~28 GB de VRAM solo para los gradientes (fp32). Para modelos de 70B o 405B, el full fine-tuning es imposible en hardware accesible.

LoRA — Low-Rank Adaptation

W' = W₀ + ΔW = W₀ + B · A   donde B ∈ ℝd×r, A ∈ ℝr×k, r ≪ min(d, k)

W₀

Peso original del modelo base. Congelado (frozen). No se actualiza.

ΔW = B·A

Actualización de bajo rango. Solo B y A se optimizan.

r (rango)

Hiperparámetro clave. Valores típicos: 4, 8, 16, 64. Controla complejidad vs. eficiencia.

α / r (escala)

Factor de escala. α normalmente = r. Permite ajustar la magnitud del update.

Inicialización: A ~ Gaussian(0, σ²), B = 0 → ΔW = 0 al inicio (no perturba el modelo base).
En inferencia: W' = W₀ + BA se fusiona → cero overhead de latencia.

LoRA visual: dos caminos y el rango r

La entrada x pasa por W₀ (congelado) y, en paralelo, por A → B (entrenable). Los resultados se suman.

QLoRA — Cuantización + LoRA

QLoRA (Dettmers et al., 2023) combina cuantización NF4 (4-bit) del modelo base con adaptadores LoRA en fp16/bf16. Resultado: Mistral 7B cabe en una sola GPU de 6 GB con calidad casi indistinguible del full fine-tuning.

NF4 Quantization

Normal Float 4-bit: cuantiza pesos del modelo base a 4 bits usando una distribución normal centrada. Reduce memoria 4×.

Double Quantization

Cuantiza también las constantes de cuantización. Ahorra ~0.37 bits/parámetro adicional.

Paginación de memoria

Usa unified memory de NVIDIA para manejar spikes de VRAM. Evita OOM durante el entrenamiento.

Adaptadores LoRA bf16

Los adaptadores LoRA siguen en bf16/fp16 para gradientes estables. Solo ellos se actualizan.

¿A dónde se va la VRAM?

Memoria estimada para entrenar Mistral 7B (7.24 B parámetros), separada por componente

pesos del modelogradientes estados del optimizador (Adam)adaptadores LoRA (pesos + grads + Adam)
Bytes por parámetro: fp32 = 4, bf16 = 2, NF4 ≈ 0.5. Adam guarda 2 estados por parámetro entrenable (8 B en fp32, ~2 B en 8-bit). Con LoRA, el modelo base no tiene gradientes ni estados de Adam: solo los ~14 M de parámetros del adaptador.
Estimación sin activaciones (dependen del batch y la longitud de secuencia; gradient checkpointing las reduce) ni overhead del framework. Las cifras reales varían según la configuración.

PEFT — Panorama de Métodos

LoRA ★ Recomendado

Matrices de bajo rango en pesos de atención. Fácil de implementar, ampliamente soportado.

Calidad relativa: Alta

AdaLoRA · Variante adaptativa

Asigna rango dinámicamente según importancia del peso. Más eficiente que LoRA fijo.

Calidad relativa: Alta

IA³ · Muy eficiente

Solo escala vectores internos. Parámetros mínimos (~0.01 %). Ideal para recursos muy limitados.

Calidad relativa: Media-Alta

Prefix Tuning · Sin tocar pesos

Aprende prefijos de tokens 'virtuales' en cada capa. No modifica pesos del modelo.

Calidad relativa: Media

Prompt Tuning · Más simple

Solo aprende tokens suaves en la entrada. Muy pocos parámetros pero menos flexible.

Calidad relativa: Media

Adapter Layers · Clásico (2019)

Inserta pequeñas capas FFN entre capas del Transformer. Más overhead en inferencia.

Calidad relativa: Alta

En la Práctica — Fine-tuning con LoRA y HuggingFace

from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model, TaskType
from trl import SFTTrainer

# 1. Cargar modelo base
model = AutoModelForCausalLM.from_pretrained("mistralai/Mistral-7B-v0.1",
                                             load_in_4bit=True)   # QLoRA
# 2. Configurar LoRA
lora_cfg = LoraConfig(
    r=16, lora_alpha=32,
    target_modules=["q_proj","k_proj","v_proj","o_proj"],
    lora_dropout=0.05, task_type=TaskType.CAUSAL_LM
)
model = get_peft_model(model, lora_cfg)
model.print_trainable_parameters()  # → ~0.24% of params

# 3. Entrenar con SFTTrainer (pares instrucción-respuesta)
trainer = SFTTrainer(model=model, train_dataset=dataset, ...)
trainer.train()

¿Por qué combinar DAPT + SFT + LoRA?

Conocimiento de dominio (DAPT)

El modelo entiende terminología especializada antes de aprender a responder.

Comportamiento instruccionable (SFT)

Pares instrucción-respuesta enseñan el formato y tono deseado.

Eficiencia de recursos (LoRA)

Ejecutable en 1 GPU de consumo. Fine-tuning de horas, no días.

Modularidad

Los adaptadores LoRA son archivos pequeños (~50 MB). Fácil versionado y distribución.

¿Cómo evaluamos el modelo entrenado?

Perplejidad (PPL)

Mide qué tan bien el modelo predice texto de validación. PPL baja = modelo más seguro en sus predicciones. Útil para DAPT: comparar PPL en corpus del dominio antes/después.

MT-Bench / AlpacaEval

Benchmarks de calidad de instrucción. Usan un LLM juez (GPT-4) para comparar respuestas. Esencial para evaluar SFT.

Métricas de dominio

Dependen del caso de uso: F1, accuracy, ROUGE, BLEU, exactitud en Q&A cerradas, métricas clínicas, legales, etc.

Regresión general

Comparar en benchmarks generales (MMLU, HellaSwag, ARC) para detectar olvido catastrófico post fine-tuning.

PPL = exp( −(1/N) · Σ log p(tokenᵢ | tokens anteriores) )
