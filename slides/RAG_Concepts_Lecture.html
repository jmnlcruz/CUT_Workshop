The Problem with LLMs

CUTOFF

Knowledge Cutoff

LLMs are trained on data up to a fixed date. A model trained in 2023 knows nothing about a paper published in 2024.

HALLUC.

Hallucination

When a model doesn't know something, it may invent plausible-sounding but incorrect answers. This is dangerous in medical contexts.

Confident ≠ correct. Fluent text gives no signal about whether a fact was actually learned.
RAG solves both: it grounds the model in documents YOU supply — no retraining needed.

Document Processing & Chunking

Why can't we pass the whole document to the LLM?

Context window limit

Most LLMs accept 4k–32k tokens. A textbook = millions of tokens.

Cost

Longer prompts = more compute and API cost at inference time.

Relevance

Passing irrelevant paragraphs confuses and degrades the model.

How chunking works:

Yellow = overlap zone — ensures sentences at boundaries are not cut mid-meaning.

Chunking Playground

Move the sliders and watch how chunk size and overlap split a health document

Smaller chunks → more precise retrieval but less context per chunk. More overlap → safer boundaries but duplicated text in the index. The exercise uses 500 / 50.

Embeddings

Converting text into numbers that capture meaning

An embedding is a vector of floating-point numbers (e.g. 384 values) where texts with similar meaning produce vectors that are close together in space. We compare them using cosine similarity.

Input textEmbedding vector (first 3 of 384 dims)Verdict
"heart attack symptoms"→[0.12, -0.34, 0.89, ...]similar (medical synonym)
"myocardial infarction"→[0.11, -0.31, 0.91, ...]similar (medical synonym)
"spaghetti carbonara"→[-0.70, 0.55, -0.12, ...]different (unrelated topic)
Model used: all-MiniLM-L6-v2  |  80 MB  |  384 dimensions  |  fast on CPU

Exploring the Embedding Space

Click any phrase to use it as the query — similarity is the angle between vectors

Query:

cos(θ) = A·B / (‖A‖‖B‖)
≈ 1 same direction (same meaning)  ·  ≈ 0 unrelated  ·  < 0 opposite
Only the angle matters, not the arrow length. Real embeddings have 384 dimensions; this is a 2-D illustration.

Mistral 7B + 4-bit Quantization

How do we run a 7-billion-parameter model on a free Colab GPU?

VRAM required:
NF4 Quantization
16 bits → 4 bits
Size: 4x smaller
Quality loss: <1%
double_quant=True saves an extra 0.5 GB by compressing the scale constants too.
Mistral 7B with nf4 uses ~4-5 GB VRAM — well within the T4's 16 GB.

How NF4 Quantization Works

A block of weights is scaled to [-1, 1], then each weight snaps to 1 of 16 levels → a 4-bit code

1. scale = absmax of the block   2. normalise w / scale   3. snap to nearest NF4 level   4. store 4-bit code + 1 scale per 64 weights.
NF4 levels are quantiles of a normal distribution — denser near 0, where most weights live. double_quant also quantizes the scales (≈0.5 → 0.13 bits per weight).

Evaluating RAG Quality

How do we know the system is working well?

FIDELITY

Does the answer stay within the retrieved context?

Penalises hallucinations. If the model invents facts not in the chunks, this score drops.

ANSWER RELEVANCE

Does the answer address the question?

Cosine similarity between the question embedding and the answer embedding.

CONTEXT RECALL

Did retrieval surface the right passages?

Max cosine similarity between the answer and any single retrieved chunk.

Advanced: the RAGAS library automates all three metrics using an LLM as judge. Try it after the exercise.

Key Takeaways

LLMs

LLMs have fixed knowledge

RAG extends any model to answer questions about documents it never saw during training.

CHUNK

Chunk wisely

Chunk size and overlap directly affect retrieval quality — experiment with both.

EMBED

Embeddings are the bridge

They let us compare meaning mathematically, not just keyword matching.

QUANT

Quantization makes it practical

4-bit NF4 shrinks a 28 GB model to ~4 GB with negligible quality loss.

EVAL

Always evaluate

Faithfulness, relevance, and context recall are your three core RAG health metrics.
